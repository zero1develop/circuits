# Trusted setup

## Status

The Zero1develop phase-2 trusted setup has not been published yet. The
[`zero1develop/ceremony`](https://github.com/zero1develop/ceremony) repository is the intended
coordination and transcript location. Until that repository publishes a completed transcript and a
release containing verified artifacts, keys generated by `setup` or `setup:all` are development-only
and must not be deployed.

The ceremony covers 26 Groth16 circuits: `deposit` and the 25 `transact_NxM` variants from `1x1` to
`5x5`.

## Ceremony requirements

Before accepting contributions:

1. Freeze the Circom version, source tree and `circuits.json`.
2. Compile all 26 circuits reproducibly and publish the SHA-256 of every `.r1cs` and `.wasm` file.
3. Verify that every circuit fits within the phase-1 file's 2^17 capacity.
4. Initialize a separate phase-2 contribution chain for every circuit.
5. Verify every contribution before passing its output to the next participant.
6. Apply a pre-announced public-randomness beacon after the participant phase.
7. Publish the full transcript, final keys, verification keys, Solidity verifiers and their hashes.

The final ceremony release must record the actual dates, participant and contribution counts, beacon
source and value, transcript SHA-256, and final artifact hashes. Do not add placeholder or copied values
to this document.

## Verifying final keys

After the ceremony release is published, each final key must verify against the exact released R1CS and
the phase-1 file:

```bash
npx snarkjs zkey verify \
  build/deposit/deposit.r1cs \
  ppot_0080_17.ptau \
  build/deposit/groth16_pkey.zkey
```

Repeat this command for all 26 circuits and compare every artifact SHA-256 with the ceremony release.
Exported verification keys and Solidity verifiers must be regenerated from those verified final zkeys.

## Development keys

The following commands create single-contributor development keys:

```bash
ALLOW_DEV_KEYS=1 pnpm run setup deposit
ALLOW_DEV_KEYS=1 pnpm run setup:all
```

They are suitable only for local tests. Never publish or deploy them as ceremony output. Any circuit,
compiler or constraint-system change invalidates its existing phase-2 key and requires a new ceremony
for the affected circuit.
